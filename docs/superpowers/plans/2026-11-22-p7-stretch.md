# P7 stretch (Loops, Ask, Triage, Meeting notes, MCP completeness) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish P7's stretch items: agents that run on a schedule or on events (Loops), a workspace question box that answers from Plane's own data with links (Ask), suggested assignee, labels, project and duplicates for new items (Triage), work items proposed from pasted meeting notes, and the MCP gaps that still answer "not available on this edition".

**Architecture:** One small AI layer (`plane/utils/ai_calls.py`) wraps every Claude Messages call made for a person (Ask, Triage, Meeting notes): workspace key, monthly limit, usage ledger. Loops reuse the P7 cloud-run path: `start_managed_run` is split so a run can target a project instead of a work item, and a beat job starts due loops as their owner (a person). Ask runs a server-side tool loop over read-only helpers that apply the asking person's visibility. MCP gaps are closed in the API (features, parallel cycles, customers) so the official MCP tools work unchanged, plus one fork tool for project updates.

**Tech Stack:** Django 5 / DRF / Celery / Postgres (`django.contrib.postgres.search` for duplicate candidates), Anthropic Python SDK (Messages API with tools; `client.beta.sessions` for Loops), React + MobX + SWR + `@makeplane/propel`, the Plane MCP image in `deployments/plane-mcp`.

**Spec:** `docs/superpowers/specs/2026-11-20-product-roadmap-design.md`, P7 stretch items 11, 14, 15, 16, 17 (Plane PLAT-38, PLAT-41, PLAT-42, PLAT-43, PLAT-44). Builds on `docs/superpowers/plans/2026-11-22-p7-agent-native.md`; run `docs/superpowers/plans/2026-11-22-p7-follow-ups.md` first (Task 1 here changes `spent_this_month_cents`, which follow-up Task 3 narrows to managed runs).

- `managed_agents.start_managed_session(project, agent, delegated_by, title, brief, issue=None, loop=None, instructions="") -> AgentRun` holds today's checks and session start; `start_managed_run(issue, agent, delegated_by, instructions)` builds `build_brief(issue, instructions)` and calls it. - `next_run_after(schedule, after: datetime) -> datetime` (strictly after; hour → next full hour; day → next `at`; week → next `weekday` at `at`).

- `run_loop(loop, reason: "schedule"|"event"|"manual", events=()) -> AgentRun | None`: pauses the loop (`is_active=False`, `last_error` set, returns None) when the agent is inactive or the owner is no longer an active project member with role ≥ 15; on `AgentError` from the start (limit, not set up) records `last_error`, keeps the loop active, returns None; else sets `last_run_at`, clears `last_error`.
- `run_due_loops()` (beat, `cache.add("agent-loops:due", 1, 120)` guard): schedule loops with `next_run_at <= now` → `run_loop`, then `next_run_at = next_run_after(schedule, now)` (missed slots are not replayed); event loops whose `last_run_at` is older than the cooldown → `WorkspaceEvent` rows after `last_event_id` in the loop's project and `event_types`, excluding events whose actor is the loop's agent; any → `run_loop(loop, "event", rows)`; `last_event_id` advances to the newest row read either way. Each loop in its own try/except.
- Permissions: project admins (role 20) and workspace admins create, edit, pause and delete loops; the creator becomes `owner` unless an admin picks another project member (person). Agent must be an active member of the project.
- Endpoints: app `GET/POST /api/workspaces/<slug>/projects/<pid>/loops/`, `GET/PATCH/DELETE .../loops/<id>/`, `POST .../loops/<id>/run/` (run now, 409 when a run of this loop is still open), `GET .../loops/<id>/runs/` (run_payload list, newest first, 50); external read-only `GET /api/v1/workspaces/<slug>/projects/<pid>/loops/`.
- Web: a project settings "Loops" page: list (name, agent, trigger summary, next run, last run status, active toggle), form with three presets that prefill name, trigger and instructions — "Weekly project update" (week, Monday 09:00, post a project update with health and what changed), "Daily triage sweep" (day 08:00, suggest owners and labels for new unassigned items as comments), "Stale-item nudges" (day 10:00, comment on in-progress items idle 5+ days) — and a run history using `RunRow` from the agent-runs widget.
